# Spec amendment — final branding (ACCEPTED)

- **Status:** accepted — lead decision 2026-08-25 under owner delegation; implemented by units BR-1 and BR-2
- **Date:** 2026-08-25
- **Amends:** the spec header ("replace `YourCo` / `XpSearch` prefixes with final branding before
  implementation"), §2 (namespace and package naming), §5 (the npm package name in every code
  sample), §11 (the list of published package IDs)
- **ADR:** [ADR-0023](../../adr/0023-branding.md)

The spec was written against a placeholder, `YourCo`, and says so in its own header. This amendment
resolves it. **Every `YourCo` / `@yourco` in the spec is read as the value in the table below.** The
spec text itself is left frozen; this page is the authority on the names.

## What is deliberately *not* branded

The internal short prefix stays `XpSearch`, exactly as spec §2 intends: assembly names, root
namespaces (`XpSearch.Core`, `XpSearch.Widgets.Rendering`, …), the UMD global `xpsearch`, the widget
type identifiers (`XpSearch.SearchBox` and friends), the static-asset folder `xpsearch/`, the
ingestion application slug `xpsearch-tuning` and the `X-XpSearch-Api-Version` header are all
unchanged. §2's rule — keep the internal short prefix and the public branded ID distinct — is what
made this a packaging change rather than a repo-wide refactor, and it held: the rebrand touched no
type name and no wire value.

## Versioning

Nothing has been published under any of the earlier names, so there is no upgrade path to write and
no compatibility shim to ship. A package ID change is not a semver event on a package that has never
been released; the pre-1.0 version numbers are untouched.
