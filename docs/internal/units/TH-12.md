## 1. Value labels

- The wire already carries a `label` per facet value (`facets[attr][] = { value, label, count }`,
  e.g. `HotTips` → "Hot tips"). Keep a **label memory** in the search instance: every response's
  facet values update an `attribute → (value → label)` map that is never cleared by a response
  that lacks the attribute (zero hits, filtered-out values). Seed it at mount from the server-
  rendered first paint if the SSR markup carries facets; otherwise the first response fills it.
- `activeFilters` chips render `<attribute label>: <value label>` using the registry label for
  the attribute and the memory for the value, falling back to the raw value only when no label
  has ever been seen (and then title-case nothing — show it as stored; do not invent
  prettification).
- The TH-7 zero-hit fallback rows in `facetList` and `categoryTree` (selected value absent from
  the response) render the remembered label too, not the raw value. `categoryTree` nested values
  (`Sweet/Acidy` is a path) show the leaf label; the chip shows the full path joined with " › "
  using each segment's remembered label when available.

## 2. Numeric chips

`rangeFilter` chips read as a human sentence using the declaring widget's `unit`, `fromLabel`,
`toLabel` and the attribute label: `Price: up to 200`, `Price: from 50`, `Price: 50 – 200`;
with a unit: `Price: $50 – $200` (unit placement per the widget's existing formatting of its
own inputs — reuse it, don't fork it). Operators map: `gte`/`gt` → "from", `lte`/`lt` → "up to",
both → range. Never print `lte`/`gte`.
