# HW-12 — Dancing Goat sample: paired result templates (Razor + `templates.item`)

**Scope:** umbrella host only (`F:\Personal\CommunityProjects\src\`). No library changes. The umbrella
dir is NOT a git repo — edit files in place, no worktree.

## Problem

`src/Search/SearchTemplateRegistration.cs` registers a result template that never renders:

1. **Path wrong.** It points at `~/Search/Views/Products.cshtml`; the only view is
   `src/Search/Products.cshtml` (no `Views` subfolder), and its entire content is the word `Test`.
   `ServerRenderedResults.FindView` logs "view was not found" and falls back to the default card.
2. **Scoping wrong.** It scopes to the four reusable product content types
   (`ProductCoffee/Brewer/Grinder/Accessory.CONTENT_TYPE_NAME`), but the index flattens products onto
   `ProductPage` documents (`src/Search/README.md` §"Flattening"), so every hit's `contentType` is
   `DancingGoat.ProductPage` and `ServerRenderedResults.Applies` never matches.
3. **No JS half.** After hydration the client renders the built-in default card; the sample never
   demonstrates the paired `templates.item` (docs/guides/page-builder-widgets.md §"keep the two in step").

## Deliverables

### 1. Fix `src/Search/SearchTemplateRegistration.cs`

- Keep identifier `"DancingGoatSearchIndex.Products"` (an editor may already have picked it in a saved
  widget config) and name `"Products"`.
- View path → `~/Search/Products.cshtml` (file stays where it is; lazier than inventing a folder).
- Content types → `[ProductPage.CONTENT_TYPE_NAME]` only. Drop the four reusable-type usings if unused.

### 2. Rewrite `src/Search/Products.cshtml` as a real product card

Model is `XpSearch.Widgets.Templates.SearchResultViewModel` (add `@using` + `@model`). Follow the
default card `libraries/.../XpSearch.Widgets/Components/Widgets/XpSearch/_Result.cshtml` for shell
classes (`xps-result`, `xps-result__body`, `__title`, `__link`, `__snippet`, `__meta`,
`__meta-item`) so theming still applies. Product-specific content, reading **explicit** attributes
(this template is product-scoped; do not depend on the widget's titleAttribute config):

- Title link: `Model.Highlight("ProductFieldName")` (falls back to encoded plain value), href `Model.Url`.
- Snippet: `Model.Highlight("ProductFieldDescription")` — render only when
  `Model.Attribute("ProductFieldDescription")` is non-empty or a highlight exists (mirror
  `SearchResultViewModel.Snippet`'s guard; `Model.Snippet` itself can't be used because it reads the
  default snippet attributes).
- Price: `Model.Attribute("ProductFieldPrice")` is raw JSON number text (e.g. `18.5`); parse with
  `decimal.TryParse(..., CultureInfo.InvariantCulture)` and render `$18.50`
  (`price.ToString("0.00", CultureInfo.InvariantCulture)`) as an `xps-result__meta-item`. Omit the
  meta list when absent (external pushed docs may lack it — no, they carry it, but guard anyway).
- No image (the index carries no `image` attribute for these documents).

### 3. New `src/wwwroot/Scripts/xpsearchResults.js` — the JS half

Plain script (no build step; match `mobileMenu.js` style). Behavior:

- Bail silently if `window.xpsearch` is undefined.
- `xpsearch.registerWidgetType('results', function (config) { return xpsearch.results({ ...config, templates: { item: ... } }); })`
  — overriding the bare `'results'` name is the supported hook (bootstrap.ts resolves registered
  factories before built-ins). Spread config as-is; it already includes `container` plus the editor's
  `titleAttribute`/`urlAttribute`/`snippetAttributes`.
- `templates.item(result, helpers)`:
  - If `result.attributes.contentType === 'DancingGoat.ProductPage'` → product card with **the same
    markup as Products.cshtml**: title = `helpers.highlight('ProductFieldName', result)`, snippet =
    `helpers.highlight('ProductFieldDescription', result)` (only when it has a value), price from
    `Number(result.attributes.ProductFieldPrice)` → `'$' + price.toFixed(2)` when finite.
  - Else → replicate the default card for the configured attributes (title from
    `config.titleAttribute || 'title'`, link from `config.urlAttribute || 'url'`, snippet = first of
    `config.snippetAttributes || ['summary','content','excerpt']` whose highlight/value is non-empty,
    contentType meta). `defaultResultItem` is NOT exported from the bundle — reimplement (~10 lines
    with `helpers.html` / `helpers.highlight`). Skip the image line (no image attribute in this index).
  - Use `helpers.html` tagged templates throughout (auto-escapes interpolations; `highlight()` output
    is trusted and composes).
- The Razor card and the JS product card must produce the same visible content (title, snippet, price)
  — that parity IS the point of the sample.

### 4. Wire the script into both layouts

In `src/Views/Shared/_DancingGoatLayout.cshtml` and `_LandingPageLayout.cshtml`, directly after
`<xps-search-assets />`:

```html
<script src="~/Scripts/xpsearchResults.js" defer></script>
```

`defer` scripts run in document order before `DOMContentLoaded`, and the UMD bundle (itself deferred)
calls `mountAll()` at `DOMContentLoaded` — so the registration lands in time. Add a one-line comment
in the layout only if the surrounding markup has comment precedent; otherwise none.
