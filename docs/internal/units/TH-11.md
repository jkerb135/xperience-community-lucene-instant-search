# Unit TH-11 — The theme never changes layout: shell/default layout parity check + panel spacing regression

Owner 2026-09-03: "search 'pr' and look at the autocomplete list, there should be some spacing."
Live (after TH-7/8/9): the single Pages row sits directly under the input — option padding 0
(board: 9px 14px), row gap 3px (board: 10px), panel `margin-top` 0 (board: 8px), no "Pages"
group header, no gap before the footer.

**Root cause (systemic, not one rule):** TH-7's element reset in `default/_root.scss` zeroes
`margin`/`padding` on `:is(p, h1…h6, ul, ol, li, …)` at (0,3,1). Any *structural* spacing the
shell declares on such an element at (0,1,0) (`.xps-suggestions__option` is an `li`) is wiped
when the theme is loaded, unless the theme restates it. `_boxes.scss` restates the boxes TH-7
knew about; the suggestions rows, the panel offset and others were missed. The isolation check
cannot see this — both of its renders carry the reset. Nothing today asserts the invariant that
matters: **shell + default must lay out exactly like shell alone; the theme adds visuals only.**

Land this on top of TH-10 (same partials, same idiom) — same worktree/branch `unit/th-10`, as a
second commit, or after it merges if TH-10 is already done. Read TH-7.md, TH-10.md, `_boxes.scss`,
`themes/scripts/check-isolation.mjs`.

## 1. Layout-parity check (the acceptance)

`themes/scripts/check-layout.mjs`, wired into `npm run check`: render every fixture in
`themes/fixtures/` (a) with `shell.css` only and (b) with `shell.css + default.css` (both
palettes), and for every element under each widget root compare the **layout property set**:
`display`, `flex-direction`, `flex-wrap`, `align-items`, `justify-content`, `gap`, `row-gap`,
`column-gap`, `padding-*`, `margin-*`, `width`, `height`, `min-*`, `max-*`, `position`, `inset`,
`overflow-*`, `box-sizing`, `grid-*`, `line-height` (it moves boxes), `font-size` (ditto),
`border-*-width` (ditto). Any difference is a failure, printed like the isolation check. It must
FAIL on today's stylesheets (paste the first failing lines — the suggestions option is one) and
pass after §2. Allowed exceptions must be listed in the script with a reason (expect: none, or a
handful where the theme legitimately sizes something the shell leaves auto — argue each one).

Then fix everything it reports, by the rule: **structure lives in the shell; the theme restates
it at its own weight through `_boxes.scss` mixins (one source, two emissions) — never by
weakening the reset.** If the reset's `margin/padding: 0` on list/text elements is the recurring
culprit, it is still correct (a host `ul li { padding-left: 40px }` must lose); the answer is
coverage, so extend `_boxes.scss` until the check is clean.

## 2. Autocomplete panel spacing (the reported instance)

Per `docs/internal/design/Autocomplete.dc.html`: option rows `padding: 9px 14px`, row `gap: 10px`,
font 14px; group header `padding: 12px 14px 4px`, 11px/700/0.05em uppercase, `border-top` +
`margin-top: 6px` between groups; panel `margin-top: 8px`; footer `padding: 10px 14px`. Make the
fixture(s) reproduce the live single-group case ("pr" → one Pages row) and the mixed case.

**Group header in a single-group response:** the board shows a header on every group. Today the
header is omitted when only one group is present. Decide with the board: in `Mixed` mode always
render the header of every non-empty group (a lone "Pages" group gets its "Pages" header); in the
single-source modes (`Documents`, `QuerySuggestions`) keep today's header-less list (there are no
groups to label). Pin with tests.
