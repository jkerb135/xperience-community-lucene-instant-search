# RZ-2 — RZ-1 follow-ups: the last JS options reach C#, and the sample registers itself

**Status:** DISPATCHED 2026-09-07 (owner: "fix" on both RZ-1 docs-review findings).
**Origin:** RZ-1 slice C review (2026-09-06): (1) three JavaScript options have no C# surface, so a
developer copying the canonical plain-HTML recipe into Razor or Page Builder loses them —
`pagination`'s `padding` / `showFirst` / `showLast`, `activeFilters`' `attributeLabels`, and the
instance's `searchOnInitialLoad`; (2) `samples/CustomWidget.Dropdown` never registers its tag
helper (`AddXpSearchWidget<DropdownFacetTagHelper, DropdownFacetOptions>()`), the Page Builder
widget takes it from DI, and the sample has no `Program.cs` — only a README sentence says so.

Rules from RZ-1 §0 still bind: no change under `src/XpSearch.Widgets/Client/src/` and none under
`src/XpSearch.Core/` (STOP and report if either seems needed); one implementation per widget in its
tag helper; Page Builder ≡ tag helper byte parity; every attribute table in
`docs/guides/razor-tag-helpers.md` is generated by `TagHelperDocsTests` (run it, paste its expected
block); XML docs on every public member; zero warnings.

## 1. `pagination`: `padding`, `show-first`, `show-last`

- `PaginationOptions` gains `int? Padding`, `bool? ShowFirst`, `bool? ShowLast` (null = the JS
  default; read the defaults from `Client/src/widgets/pagination.ts` and state them in the XML doc).
  `PaginationTagHelper` binds `padding`, `show-first`, `show-last`; `BuildConfig` emits only what
  was set (reflection already skips nulls — verify that `bool?` false IS emitted, since `false` is a
  real departure from a `true` default; adjust if the reflector drops it).
- `PaginationWidgetProperties` gains `Padding` (NumberInput, min 0), `ShowFirst`, `ShowLast`
  (CheckBox) with Label/Tooltip/ExplanationText in the sibling voice, defaults equal to the JS
  defaults; `ToOptions` maps them. Editor preview: reflect `ShowFirst`/`ShowLast` in the mirrored
  markup if the preview draws those controls; otherwise a note line.

## 2. `activeFilters`: `attribute-labels`

- `ActiveFiltersOptions` gains `IReadOnlyDictionary<string, string>? AttributeLabels`.
  `ActiveFiltersTagHelper` binds `attribute-labels` as a dictionary (`attribute-labels="@labels"`);
  ALSO accept the `attribute;Label` line form the Page Builder uses (see below) so the value can be a
  string in markup — pick the smallest way (a second attribute `attribute-labels-text`, or one
  `object`-typed attribute that accepts both; say which and why). Config key `attributeLabels`.
- `ActiveFiltersWidgetProperties` gains `AttributeLabels` — a text area of `attribute;Label` lines,
  parsed with the SAME parser `FilterSortWidgetProperties.Facets` uses (find it; do not write a
  second one). TH-4 deliberately left this off the Page Builder because the labels were "JS-side";
  RZ-1 changed that premise (labels are one option, C# is one surface) — say so in the CHANGELOG.
- Host follow-up (NOT this unit, note it in the report): `src/Search/client/main.ts` overrides
  `activeFilters` to inject `ATTRIBUTE_LABELS`; with this shipped the override can go and the Razor
  page + PB widget carry the labels themselves.

## 3. Instance: `search-on-initial-load`

- `XpSearchScope` + `<xps-search>` gain `search-on-initial-load` (bool?), applied by `ApplyTo` like
  `routing` (never overwriting a mount's own value).
- Mirror `SyncStateToUrl`'s placement for the per-widget form: `SearchBoxOptions` /
  `SearchBoxWidgetProperties` gain `SearchOnInitialLoad` (bool?, PB CheckBox, default = JS default
  — read `Client/src/instance.ts`/`types.ts`), written by `SearchBoxTagHelper.BuildInstanceConfig`
  beside `routing`. If the existing instance-config plumbing makes one of the two placements
  redundant, keep the scope one and say why.
