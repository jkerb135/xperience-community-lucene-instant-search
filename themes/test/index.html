xperience-search — theme verification (spec §6)

Every widget fixture from themes/fixtures/, rendered four times. Each section is a separate document in an iframe so the stylesheet combinations cannot contaminate one another. Open this file straight from disk — no server, no build step. Regenerate the sections after editing a fixture with npm run build:test.

What to look for

  1. (a) shell only — every widget is laid out and legible using the host page's own colours and fonts. Nothing looks designed, nothing looks broken.
  2. (b) shell + default — the same markup, themed. Change a variable in src/default.css (say --xps-color-accent) and everything follows.
  3. (b2) shell + kentico-orange — the second shipped palette. Identical to (b) apart from the accent: same boxes, same rhythm, same type. Anything else that differs is a colour that escaped the token block.
  4. (c) shell + hostile host — clashing-host.css loads after shell with !important colours, global button/input/ul/a/mark rules and * { box-sizing: content-box }. Widgets absorb the host's palette but stay usable: nothing overflows, no control becomes unreachable.
  5. Leakage — the pink-bordered “host page sample” block appears at the top and bottom of every section, outside every .xps element. It must render identically in (a), (b) and (b2). If it differs, a widget stylesheet has leaked.

Keyboard walk-through (do this in every section)

Click into the iframe first, then walk the whole section with the keyboard only — no mouse. Every step below must be possible, and the focused element must always be visibly ringed (shell draws a 2px currentColor outline on :focus-visible).

  1. Tab from the top and keep going to the bottom of the section: you should never lose the focus ring, and never land on a control that does nothing.
  2. searchBox — type in the input, Tab to the clear button (announced “Clear the search query”), Enter resets it. The hidden reset in the empty variant must be skipped by Tab.
  3. suggestions — the open fixture is static markup, so check the wiring instead: the input is role="combobox" with aria-expanded="true", aria-controls pointing at the listbox and aria-activedescendant pointing at the option carrying xps-suggestions__option--active. Options must never take DOM focus.
  4. facetList / toggleFilter — Space toggles each checkbox; the disabled row is skipped by Tab; the whole label row is a hit area.
  5. pagination — every enabled control is a link and reachable; the disabled first/prev controls are <span aria-disabled="true"> and are correctly skipped; the current page carries aria-current="page".
  6. sortSelect — Tab to the select, change it with the arrow keys.
  7. activeFilters — Tab to each chip's remove button; its accessible name says which filter it removes, not just “×”.
  8. rangeSlider — arrow keys move each native range input by one step, Home/End jump to the ends; the numeric inputs accept typing.
  9. categoryTree — every level is reachable; the selected path carries aria-current="true".
  10. loadMore — the load-more button is reachable and stays in the DOM (disabled) when exhausted, so focus is never destroyed.
  11. Turn on “reduce motion” in the OS: the skeleton pulse in the loading fixtures must stop.
