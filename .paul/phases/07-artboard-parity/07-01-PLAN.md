<objective>
## Goal
The live demo's autocomplete panel and its no-results states are indistinguishable from the
approved artboards (`docs/internal/design/Autocomplete.dc.html`, `States.dc.html`), and a no-results
query under 1024px shows the recovery panel instead of "No more results".

## Purpose
Owner rule: shipped defaults must match the approved mockup exactly. The 2026-09-01 parity pass
covered the desktop results page only; the owner found the panel and the empty state off-design on
2026-09-03 (row icons, recent-row remove, prefix highlight, Pages meta line; empty state left-aligned,
small, no card, square chips; empty state missing in Load more mode).

## Output
- Unit spec TH-6 (written), artboards checked into `docs/internal/design/`
- Theme + client + SSR changes, fixtures/MARKUP updated, parity tests extended
- Merged, host rebuilt (widgets client bundle + sln), checklist §Z, owner visual sign-off
</objective>

<acceptance_criteria>

## AC-1: Autocomplete panel matches the board
```gherkin
Given the demo search box with suggestions enabled and a recent search recorded
When the visitor types a prefix
Then the panel shows Recent rows (clock icon, remove control), Suggestions rows (magnifier, prefix band highlight),
  Pages rows (accent title + muted meta line) and the keycap footer, matching Autocomplete.dc.html
```

## AC-2: No-results states match the board
```gherkin
Given a query with no hits (and, separately, a filtered query with no hits but N unfiltered hits)
When the results render at 1280px
Then the state is a centred white card with the board's icon size, headline, did-you-mean line and pill chips
  (or the counted line + primary Clear filters button), matching States.dc.html
```

## AC-3: Empty state in Load more mode
```gherkin
Given a viewport under 1024px (Load more swap active)
When a query returns no hits
Then the same empty state renders and the "No more results" control is hidden
```

## AC-4: Parity and gates
```gherkin
Given the merged unit
When the themes check, vitest (a11y gate), Widgets and Core suites run
Then all pass, fixtures and MARKUP.md reflect the new markup, and SSR/client empty-state markup are pinned equal
```
